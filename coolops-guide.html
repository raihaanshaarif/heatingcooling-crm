1. What CoolOps does

CoolOps keeps every part of the business in one place, from the first phone call to the money in the bank, and back again for the next service.

Lead→Quote→Job→Invoice→Payment→Maintenance reminder→Next job
  • Leads: new enquiries (phone, website, Google Ads and so on) and where each one came from.
  • Clients: customers, their properties (addresses) and the air conditioners and heaters at each property.
  • Quotes: priced quotes with up to five options (for example three sizes of split system). Clients accept online.
  • Jobs and Schedule: booked work on a calendar, coloured by technician.
  • My jobs: a phone screen for technicians with big buttons, checklists, photos, parts and customer signature.
  • Invoices and Payments: proper Australian tax invoices with GST, payments, credit notes, overdue reminders.
  • Maintenance plans: yearly or regular services, with automatic reminder emails.
  • Reports: revenue, lead sources, unpaid invoices and more, exportable for your accountant.

Everything is in Australian dollars, GST is 10%, and all times are Melbourne time, whatever device you use.

2. Who can do what

Every person gets their own login and one of three roles.

RoleWho it is forWhat they can do
Owner / AdminYou, the business ownerEverything, including Settings, Team, the Audit log, cost prices, margins and the Job profitability report.
Office / DispatcherOffice staffLeads, clients, equipment, quotes, jobs, schedule, invoices, payments and maintenance plans. Can view reports, the price book and the team. Cannot change Settings or users and cannot see cost prices or margins.

Technicians are taken straight to My jobs when they log in. If someone opens a page their role does not allow, they are sent back to their home screen.

4. Put the code on GitHub

Coolify deploys from GitHub, so the code has to live there first. The easiest way without using the command line:

  1. Unzip coolops.zip on your computer. You get a folder called coolops.
  2. Install GitHub Desktop and sign in.
  3. Choose File → Add local repository and pick the coolops folder. If it says it is not a repository, choose create a repository there.
  4. Click Publish repository, keep Keep this code private ticked, and publish.

If you prefer the command line:

cd coolops
git init
git add .
git commit -m "CoolOps"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/coolops.git
git push -u origin main
Never upload your .env file

The .env file holds passwords and secret keys. It is already listed in .gitignore so Git skips it. Do not remove that line.

5. Put it online with Coolify

Coolify builds the app with Nixpacks, which turns the code into a running container automatically. The file nixpacks.toml in the code already tells it to use Node 22 and to update the database structure every time the app starts. You only click through the steps below.

Step 1: Create the database

  1. In Coolify, open your project and click + New → Database → PostgreSQL (version 16).
  2. Click Start and wait until it shows as running.
  3. Copy the internal connection URL (it looks like postgres://postgres:LONGPASSWORD@abc123:5432/postgres). You will paste it into the app in step 3.
Tip

Use the internal URL, not the public one. The app and database talk to each other inside the server, which is faster and safer. You do not need to make the database public.

Step 2: Create the app

  1. In the same project click + New → Application and choose your GitHub repository (connect your GitHub account or the Coolify GitHub App if asked).
  2. Branch: main. Build pack: Nixpacks.
  3. Ports exposed: 3000.
  4. Leave the install, build and start commands empty. They come from the code.

Step 3: Add the settings

Open the app's Environment Variables tab and add each one from the table in section 6. At minimum: DATABASE_URL, AUTH_SECRET, AUTH_URL, APP_URL, CRON_SECRET, LEAD_WEBHOOK_SECRET.

Step 4: Keep uploaded files safe

Job photos, signatures and your logo are saved as files. Without this step they disappear every time you redeploy.

  1. Add the variables STORAGE_DRIVER=local and STORAGE_LOCAL_DIR=/app/uploads.
  2. Open the app's Persistent Storage (Storages) tab and add a volume with destination path /app/uploads.

Step 5: Your web address

  1. At your domain registrar, add an A record for app (or whatever name you like) pointing to your server's IP address.
  2. In the app's General tab, set Domains to https://app.coolingservicemelbourne.com.au. Coolify gets the HTTPS certificate for you.
  3. Make sure AUTH_URL and APP_URL use exactly this address.

Step 6: Deploy

  1. Click Deploy. The first build takes a few minutes. Watch the logs; it is finished when you see the app listening on port 3000.
  2. The first start creates all the database tables automatically.
  3. Now load data: see section 8. You cannot log in until you do, because there are no users yet.

Step 7: Daily reminders

Overdue invoice emails, service-due reminders and licence alerts run once a day.

  1. Open the app's Scheduled Tasks tab and add a task.
  2. Name: Daily reminders. Command: pnpm cron:reminders. Frequency: 0 8 * * * (8:00 every day).
  3. Coolify runs schedules in the server's time zone. Set the server's timezone to Australia/Melbourne in Coolify's server settings, or use 0 21 * * * if the server stays on UTC (8 am in summer, 7 am in winter).

To test it, click Run now (or run pnpm cron:reminders in the app's Terminal). It prints a summary such as 200 {"ok":true,"overdueEmails":0,...}. Running it twice is safe: nothing is sent twice.

7. Set up email (Resend)

  1. Sign up at resend.com.
  2. Go to Domains → Add domain and enter coolingservicemelbourne.com.au.
  3. Resend shows a few DNS records (TXT and MX). Add them at your domain registrar exactly as shown, then click Verify. It can take from minutes to a few hours.
  4. Go to API Keys → Create API key (sending access). Copy it into RESEND_API_KEY in Coolify.
  5. Set EMAIL_FROM to an address on that domain, then redeploy.
  6. Test: open a quote or invoice for a client whose email is yours and click Send.
Which emails the app sends

Quote sent, invoice sent, overdue invoice reminders (1, 7 and 14 days overdue), service-due reminders to clients, and alerts to the office (new website lead, licence or warranty expiring, service due). You can change the wording of the client emails in Settings → Email templates.

  1. In Coolify open the app and go to Terminal.
  2. Type pnpm db:seed and press Enter. Wait until it finishes.
  3. Open your web address and log in.

Run the seed only once

pnpm db:seed deletes everything in the database and starts again with demo data. Never run it after you have entered real clients, jobs or invoices.

Going live: clear the demo data

When you have finished practising, remove the example records but keep your admin login, settings and checklist templates:

  1. First take a backup (section 32).
  2. In Coolify open the database (not the app), go to Terminal, type psql -U postgres -d postgres and press Enter. (If you named the database differently, use that name after -d.)
  3. Paste the block below and press Enter. Then type \q to leave.
BEGIN;
TRUNCATE "Activity", "Attachment", "AuditLog", "Client", "Contact", "CreditNote", "Equipment",
  "InventoryItem", "Invoice", "InvoiceLineItem", "Job", "JobAssignment", "JobChecklistItem",
  "JobEquipment", "JobLineItem", "Lead", "MaintenancePlan", "MaintenancePlanEquipment",
  "Notification", "Payment", "PriceBookItem", "Property", "Quote", "QuoteLineItem", "QuoteOption",
  "Reminder", "Supplier", "TechnicianLicence", "TimeEntry", "Session" CASCADE;
DELETE FROM "User" WHERE email <> 'admin@coolops.local';
UPDATE "Counter" SET value = 0;
COMMIT;

This removes all leads, clients, quotes, jobs, invoices, payments, the demo price book and the three demo staff logins, and restarts numbering at 0001. Then follow the first-day checklist, including changing the admin email and password.

9. First-day checklist

Log in as admin@coolops.local and work down this list.

  1. Secure the admin login. Go to Team, open Alex Morgan (the admin), change the name and email to your own and save. Then go to My account (round account button, top right) and change the password.
  2. Business details. Settings → Business: legal business name, ABN, address, phone, email, and upload your logo (PNG or JPG, under 2 MB).
  3. GST, terms and bank details. Settings → Invoicing: tick Registered for GST if you are, choose default payment terms, enter BSB and account details (they print on every invoice), quote validity days, invoice footer and quote terms and conditions.
  4. Numbering. Settings → Numbering: set prefixes (for example INV-) and, if you are moving from another system, set the next invoice, quote and job number so you carry on from where you were.
  5. Email wording. Settings → Email templates: adjust the subject and message for quotes, invoices, overdue reminders and service reminders.
  6. Job checklists. Settings → Checklists: edit the steps technicians tick off for each job type, one item per line.
  7. Add your staff. Team → Add user for each person: name, login email, mobile, role, calendar colour, hourly cost (for profit reports) and a starting password. Add each technician's licences (ARC, gas, electrical…) with expiry dates.
  8. Price book. Price book → New item for your common services, parts and units, with cost and sell prices (ex GST).
  9. Website form. Connect your website's enquiry form (section 29).
  10. Test the whole flow once with yourself as the client: lead → quote → accept → job → complete → invoice → payment.

12. Leads

A lead is an enquiry that is not yet a customer job. Website enquiries arrive here automatically; you add phone calls yourself.

Leads move through: New → Contacted → Site visit booked → Quoted → Won, or Lost.

How do I add a lead from a phone call?

  1. Go to Leads and click New lead.
  2. Fill in name, phone and/or email, suburb and postcode, Service, Source (Phone call, Google Ads, Referral…), urgency, estimated value and what they need.
  3. Optionally assign it to someone and set a Follow up on date. Save.

How do I move a lead along?

Use the Pipeline view and drag the card to the next column, or open the lead and change Lead status. Switch to Table view for a sortable list.

How do I turn a lead into a customer?

  1. Open the lead and click Convert.
  2. Pick an existing client or create a new one (choose client type and service address).
  3. Under Then choose Create a quote, Create a job (marks lead won), or Just create the client.
  4. CoolOps creates the client and property and takes you to the new quote or job. The lead is linked so reports can show which source won the work.

How do I mark a lead as lost?

Open it, click Mark lost and choose the reason (Too expensive, Went with another company, No reply, Not ready / timing, Outside service area, Did it themselves, Other). The reasons appear in reports so you can learn from them.

13. Clients, properties and contacts

  • Client: who pays. Types: Residential, Commercial, Real estate / Property manager, Builder.
  • Property: where the work is done. One client can have many (useful for agents and landlords). Each property has access notes, parking, pets and keys/lockbox details for technicians.
  • Contacts: other people at a client, such as a tenant or site manager.

How do I add a client?

  1. Clients → New client.
  2. Enter name, type, company (if any), email, phone, ABN for businesses, how they found you and the address. The address becomes their first property.
  3. Use Do not service to warn the office when booking work for difficult clients.

What is on a client page?

Tabs with everything about them: overview (properties, contacts, totals such as lifetime value and outstanding balance), their leads, quotes, jobs, invoices, payments, maintenance plans and an activity timeline. Add call notes with Add note.

How do I add another property?

On the client page click Add property. Open a property to see its equipment and job history.

16. Quotes

Statuses: Draft → Sent → Viewed → Accepted, or Declined / Expired (after the valid-until date).

How do I write a quote?

  1. Quotes → New quote (or convert a lead).
  2. Pick the client and site, give it a title and check the Valid until date.
  3. Add lines: from the price book or as custom lines. Each line has quantity, price and GST on/off. Totals and GST are calculated for you.
  4. Need choices? Add up to five options (for example Good / Better / Best, or 2.5 kW / 3.5 kW / 5 kW). The client picks one.
  5. Add an introduction and check the terms, then Save quote (or Save draft).

How do I send it?

On the quote page click Send. The client gets an email with a private link where they can see the options, download the PDF, and accept or decline online (to accept, they choose an option and type their name). When they open it the status becomes Viewed; when they accept, you get a notification.

Other buttons: PDF (download), Edit, and under ⋯: Copy client link (to paste into a text message), Open client view, Record acceptance or Record decline (when they tell you by phone), Duplicate, Delete.

Accepted. Now what?

Click Create job. The chosen option's lines are copied into a new job ready to schedule.

17. Jobs

Job types: Installation, Service / Maintenance, Repair, Emergency, Inspection, Warranty, Quote visit. Priority: Low, Normal, High, Emergency.

Statuses: Unscheduled → Scheduled → En route → In progress → Completed → Invoiced, plus On hold (for example waiting for parts) and Cancelled.

How do I create a job?

  1. Jobs → New job, or click an empty time on the Schedule, or Create job on an accepted quote.
  2. Choose client and site, job type, priority, title and description.
  3. Set start and end time (or leave unscheduled to book later) and estimated minutes.
  4. Choose the technician(s). Save.

What is on a job page?

  • Details and status buttons: On my way, Start job, Put on hold / Resume, Complete, Cancel.
  • Technicians assigned.
  • Checklist: added from the template for the job type (Add checklist), plus your own items.
  • Equipment at the site worked on in this job.
  • Parts and labour: lines that go on the invoice (Add part / labour or from the price book).
  • Time on site: starting the job starts a timer automatically; completing stops it.
  • Photos and files (before / after), notes, customer signature.
  • Completion details: work performed, refrigerant recovered and added (kg) and gas compliance certificate number.
  • Invoices raised from this job.

Under ⋯: Edit, Unschedule (moves it back to the unscheduled list) and Delete job (not possible once it has an invoice).

19. Technicians: My jobs

Built for a phone. Technicians log in at your web address and land here. Tip: on the phone, use the browser's Add to Home Screen so it opens like an app.

A typical job, step by step

  1. Open today's job from the list (In progress and Upcoming).
  2. Tap Directions to open the address in Maps. Check access, parking, pets and key notes.
  3. Tap On my way when leaving.
  4. Tap Start job on arrival. The time-on-site timer starts.
  5. Tick the Checklist as you go.
  6. Add Photos (choose before / after) straight from the camera.
  7. Add Parts & labour used and any notes.
  8. Fill in Completion details: work performed, refrigerant recovered/added, gas certificate number if gas work.
  9. Hand the phone to the customer for the Customer signature.
  10. Tap Complete. The office sees it straight away and can invoice it.

20. Invoices

Statuses are worked out automatically from the money and dates: Draft → Sent → Partially paid / Overdue → Paid, or Void.

Every invoice is a valid Australian Tax Invoice: your business name and ABN, the words "Tax Invoice", invoice number and date, the client (and their ABN), each line, GST and total, and your bank details.

How do I invoice a finished job?

  1. Open the job and click Create invoice.
  2. Choose Invoice the job in full. The job's parts and labour lines are copied in. Any deposit or progress invoices already raised are deducted automatically.
  3. Check it, then click Send.

Deposits and progress claims (big installs)

On the job, Create invoice → Deposit invoice… or Progress claim… and enter a percentage of the job value (30% is suggested for deposits). The final full invoice subtracts them.

An invoice without a job

Invoices → New invoice, pick the client, add lines, set issue date, due date and payment terms.

Buttons on an invoice

  • Send / Resend: emails the client a link to view and download the PDF.
  • PDF: download it yourself (to print or attach elsewhere).
  • Record payment: see Payments.
  • Edit: change lines or dates.
  • Under ⋯: Copy client link, Open client view, Mark as sent (if you gave it to them another way), Issue credit note, Void invoice, Delete draft.

Credit note or void?

  • Credit note: you need to reduce what the client owes (a discount after the fact, a returned part). Enter the amount inc GST and a reason. It gets its own number (CN-0001) and lowers the balance.
  • Void: the invoice should never have existed (wrong client, duplicate). It stays on record, marked Void, and is not counted.
Numbers never repeat

Invoice, quote, job and credit note numbers are given out one at a time and are never reused, as the ATO expects.

21. Payments

How do I record a payment?

  1. Open the invoice and click Record payment (or use the button on the Dashboard or Payments page).
  2. Enter the amount (inc GST), date received, method (Card (EFTPOS), Bank transfer, Cash, Cheque, Other) and a reference such as the bank transaction ID.
  3. Save. The balance and status update immediately: part payments show Partially paid, full payment shows Paid.
  • Refund: record a payment and tick This is a refund to the client.
  • Mistake: remove the payment from the invoice's payments list. The balance is recalculated.
  • The Payments page lists all money received with totals, filters and the most used method.

22. Maintenance plans

For clients on a regular service (for example an annual split system service). This is your repeat revenue.

  1. Maintenance → New plan.
  2. Choose client and site, give the plan a name, tick the equipment it covers, choose frequency (Monthly, Quarterly, Six-monthly, Yearly), price per visit (ex GST) and start date.
  3. Create plan. The Next service due date is worked out for you.
  • 14 days before a service is due, the client gets a reminder email and the office gets a notification.
  • Click Create job on a plan to make the service job. When that job is completed, the next due date moves forward by one period.
  • Untick Active to pause a plan; inactive plans do not send reminders.

23. Automatic reminders

Once a day (the scheduled task from section 5, step 7) CoolOps:

  1. marks unpaid invoices past their due date as Overdue and emails the client at 1, 7 and 14 days overdue (each only once);
  2. emails clients whose maintenance service is due within 14 days, and tells the office;
  3. warns about technician licences and equipment warranties expiring within 30 days;
  4. marks quotes past their valid-until date as Expired.

Nothing is ever sent twice, even if the task runs more than once in a day.

29. Website enquiry form

Your website's contact form can send enquiries straight into Leads. The office gets a notification and an email. If the same person enquires again within 24 hours (same email or phone), it is added to the existing lead instead of making a duplicate.

The form must send a POST request to https://YOUR-APP-ADDRESS/api/leads/webhook with the header x-api-key set to your LEAD_WEBHOOK_SECRET and a JSON body like this:

{
  "name": "Jane Citizen",
  "email": "jane@example.com",
  "phone": "0412 345 678",
  "suburb": "Brunswick",
  "postcode": "3056",
  "service": "Split system service",
  "brand": "Daikin",
  "message": "Two units, one is making a rattling noise.",
  "utm_source": "google",
  "utm_medium": "cpc",
  "utm_campaign": "aircon-service",
  "gclid": "abc123",
  "site": "coolingservicemelbourne.com.au"
}
  • name plus email or phone are required; everything else is optional.
  • utm_* and gclid come from your ad links. A gclid marks the lead as Google Ads so the Lead sources report shows your ad return.
  • Add a hidden, empty field called website to your form. Bots fill it in and are ignored.
  • At most 10 enquiries per minute from one address are accepted, to stop spam floods.

More than one website

All your websites use the same address and the same key. You do not need anything new in CoolOps for each site.

  1. On each website, point the enquiry form at https://YOUR-APP-ADDRESS/api/leads/webhook with the header x-api-key, exactly as above.
  2. Add one more field to each site's form called site, set to that website's name, for example melbourneaircon.com.au. In most form plugins this is a hidden field with a fixed value.
  3. Leads then show the website under their source, on the Leads board, in the table and on the lead page, so you can see which site brings in work.

If a form leaves out site but sends straight from the visitor's browser, CoolOps reads the website's address from the request automatically. Sending site is still the most reliable way.

If the forms send straight from the browser, list every website in LEAD_WEBHOOK_ALLOWED_ORIGINS, separated by commas, for example https://coolingservicemelbourne.com.au,https://melbourneaircon.com.au.

Who should connect it?

Give your web developer this section. The safest way is for your website's server to send the request (for example a WordPress form plugin with a "webhook" option, such as WPForms, Gravity Forms or Contact Form 7 with a webhook add-on), so the secret key is never visible in the browser.

Test it

curl -X POST https://YOUR-APP-ADDRESS/api/leads/webhook \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_LEAD_WEBHOOK_SECRET" \
  -d '{"name":"Test Lead","phone":"0400 000 000","suburb":"Richmond","site":"melbourneaircon.com.au"}'

A new lead called "Test Lead" should appear on the Leads board, showing Website form · melbourneaircon.com.au.

31. Updating the app

  1. Get the new code into your GitHub repository (commit and push, or GitHub Desktop → Push origin).
  2. In Coolify open the app and click Redeploy. Or turn on Auto Deploy so every push to main deploys by itself.
  3. When the app starts it updates the database structure automatically (prisma migrate deploy). Your data is kept.
Before a big update

Take a database backup first (next section). If a deploy fails, Coolify keeps the previous version running, and you can roll back from the Deployments list.

32. Backups and restoring

Database (most important)

  1. Open the PostgreSQL database in Coolify and go to Backups.
  2. Add a scheduled backup, for example daily at 2 am (0 2 * * *), and keep at least 14.
  3. Strongly recommended: add an S3 storage destination in Coolify (Cloudflare R2, Backblaze B2, AWS) so backups are stored off the server. If the server dies, backups on it die too.
  4. Click Backup now once to check it works.

Restoring

From the database's Backups list choose a backup and restore it (or download it and import with pg_restore / psql). Restoring replaces the current data with the backup's, so only do it when you mean to.

Uploaded files

Photos, signatures and the logo live in the /app/uploads volume. Back up the server (most VPS providers offer snapshots) or use S3 storage for uploads (STORAGE_DRIVER=s3), which keeps files off the server.

34. Questions and answers

Do I need Docker?

No. Coolify builds and runs the container for you. There are no Docker files in the code on purpose.

Can clients log in?

Not with an account. They get private links to their quotes and invoices, where they can view, download, and accept or decline quotes.

Can clients pay by card online?

Not yet (see section 36). Record card payments taken on your EFTPOS terminal as "Card (EFTPOS)".

Can I continue my old invoice numbers?

Yes: Settings → Numbering → set the next invoice number.

I'm not registered for GST.

Untick Registered for GST in Settings → Invoicing. GST is no longer added and PDFs are titled "Invoice" instead of "Tax Invoice".

Can I delete an invoice?

Only drafts. Sent invoices are voided instead, so your numbering and records stay complete for tax.

How many users can I have?

As many as you like. There is no per-user cost.

Is my data safe?

Passwords are stored encrypted (hashed), every page checks the person's role, the site runs over HTTPS, and every change is recorded in the audit log. Keep daily off-server backups (section 32).
