1. What CoolOps does

CoolOps keeps every part of the business in one place, from the first phone call to the money in the bank, and back again for the next service.

Lead→Quote→Job→Invoice→Payment→Maintenance reminder→Next job
  • Leads: new enquiries (phone, website, Google Ads and so on) and where each one came from.
  • Clients: customers, their properties (addresses) and the air conditioners and heaters at each property.
  • Quotes: priced quotes with up to five options (for example three sizes of split system). Clients accept online.
  • Jobs and Schedule: booked work on a calendar, coloured by technician.
  • My jobs: a phone screen for technicians with big buttons, checklists, photos, parts and customer signature.
  • Invoices and Payments: proper Australian tax invoices with GST, payments, credit notes, overdue reminders.
  • Maintenance plans: yearly or regular services, with automatic reminder emails.
  • Reports: revenue, lead sources, unpaid invoices and more, exportable for your accountant.
  • Add-ons: stock in the warehouse and each van, SMS texts to clients, live Xero sync, jobs in each person's Google Calendar, and route planning for technicians (sections 30 to 34).

Everything is in Australian dollars, GST is 10%, and all times are Melbourne time, whatever device you use.

2. Who can do what

Every person gets their own login and one of three roles.

RoleWho it is forWhat they can do
Owner / AdminYou, the business ownerEverything, including Settings, Team, the Audit log, cost prices, margins and the Job profitability report.
Office / DispatcherOffice staffLeads, clients, equipment, quotes, jobs, schedule, invoices, payments and maintenance plans. Can view reports, the price book and the team. Cannot change Settings or users and cannot see cost prices or margins.
TechnicianField staffOnly My jobs: the jobs assigned to them. They can update status, tick the checklist, add photos, parts and notes, capture a signature and complete the job. They do not see prices.

Technicians are taken straight to My jobs when they log in. If someone opens a page their role does not allow, they are sent back to their home screen.

4. Put the code on GitHub

Coolify deploys from GitHub, so the code has to live there first. The easiest way without using the command line:

  1. Unzip coolops.zip on your computer. You get a folder called coolops.
  2. Install GitHub Desktop and sign in.
  3. Choose File → Add local repository and pick the coolops folder. If it says it is not a repository, choose create a repository there.
  4. Click Publish repository, keep Keep this code private ticked, and publish.

If you prefer the command line:

cd coolops
git init
git add .
git commit -m "CoolOps"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/coolops.git
git push -u origin main
Never upload your .env file

The .env file holds passwords and secret keys. It is already listed in .gitignore so Git skips it. Do not remove that line.

5. Put it online with Coolify

Coolify builds the app with Nixpacks, which turns the code into a running container automatically. The file nixpacks.toml in the code already tells it to use Node 22 and to update the database structure every time the app starts. You only click through the steps below.

Step 1: Create the database

  1. In Coolify, open your project and click + New → Database → PostgreSQL (version 16).
  2. Click Start and wait until it shows as running.
  3. Copy the internal connection URL (it looks like postgres://postgres:LONGPASSWORD@abc123:5432/postgres). You will paste it into the app in step 3.
Tip

Use the internal URL, not the public one. The app and database talk to each other inside the server, which is faster and safer. You do not need to make the database public.

Step 2: Create the app

  1. In the same project click + New → Application and choose your GitHub repository (connect your GitHub account or the Coolify GitHub App if asked).
  2. Branch: main. Build pack: Nixpacks.
  3. Ports exposed: 3000.
  4. Leave the install, build and start commands empty. They come from the code.

Step 3: Add the settings

Open the app's Environment Variables tab and add each one from the table in section 6. At minimum: DATABASE_URL, AUTH_SECRET, AUTH_URL, APP_URL, CRON_SECRET, LEAD_WEBHOOK_SECRET.

Step 4: Keep uploaded files safe

Job photos, signatures and your logo are saved as files. Without this step they disappear every time you redeploy.

  1. Add the variables STORAGE_DRIVER=local and STORAGE_LOCAL_DIR=/app/uploads.
  2. Open the app's Persistent Storage (Storages) tab and add a volume with destination path /app/uploads.

Step 5: Your web address

  1. At your domain registrar, add an A record for app (or whatever name you like) pointing to your server's IP address.
  2. In the app's General tab, set Domains to https://app.coolingservicemelbourne.com.au. Coolify gets the HTTPS certificate for you.
  3. Make sure AUTH_URL and APP_URL use exactly this address.

Step 6: Deploy

  1. Click Deploy. The first build takes a few minutes. Watch the logs; it is finished when you see the app listening on port 3000.
  2. The first start creates all the database tables automatically.
  3. Now load data: see section 8. You cannot log in until you do, because there are no users yet.

Step 7: Daily reminders

Overdue invoice emails, service-due reminders and licence alerts run once a day.

  1. Open the app's Scheduled Tasks tab and add a task.
  2. Name: Daily reminders. Command: pnpm cron:reminders. Frequency: 0 8 * * * (8:00 every day).
  3. Coolify runs schedules in the server's time zone. Set the server's timezone to Australia/Melbourne in Coolify's server settings, or use 0 21 * * * if the server stays on UTC (8 am in summer, 7 am in winter).

To test it, click Run now (or run pnpm cron:reminders in the app's Terminal). It prints a summary such as 200 {"ok":true,"overdueEmails":0,...}. Running it twice is safe: nothing is sent twice.

7. Set up email (Resend)

  1. Sign up at resend.com.
  2. Go to Domains → Add domain and enter coolingservicemelbourne.com.au.
  3. Resend shows a few DNS records (TXT and MX). Add them at your domain registrar exactly as shown, then click Verify. It can take from minutes to a few hours.
  4. Go to API Keys → Create API key (sending access). Copy it into RESEND_API_KEY in Coolify.
  5. Set EMAIL_FROM to an address on that domain, then redeploy.
  6. Test: open a quote or invoice for a client whose email is yours and click Send.
Which emails the app sends

Quote sent, invoice sent, overdue invoice reminders (1, 7 and 14 days overdue), service-due reminders to clients, and alerts to the office (new website lead, licence or warranty expiring, service due). You can change the wording of the client emails in Settings → Email templates.

8. Demo data or a clean start

A new database has no users, so you load the starter data once. This creates 4 logins, business settings, checklist templates and a realistic set of example clients, quotes, jobs and invoices you can practise on.

  1. In Coolify open the app and go to Terminal.
  2. Type pnpm db:seed and press Enter. Wait until it finishes.
  3. Open your web address and log in.
EmailRolePassword
admin@coolops.localOwner / AdminChangeMe123!
office@coolops.localOffice / Dispatcher
tech1@coolops.localTechnician
tech2@coolops.localTechnician (gas fitter)
Run the seed only once

pnpm db:seed deletes everything in the database and starts again with demo data. Never run it after you have entered real clients, jobs or invoices.

Going live: clear the demo data

When you have finished practising, remove the example records but keep your admin login, settings and checklist templates:

  1. First take a backup (section 37).
  2. In Coolify open the database (not the app), go to Terminal, type psql -U postgres -d postgres and press Enter. (If you named the database differently, use that name after -d.)
  3. Paste the block below and press Enter. Then type \q to leave.
BEGIN;
TRUNCATE "Activity", "Attachment", "AuditLog", "Client", "Contact", "CreditNote", "Equipment",
  "InventoryItem", "Invoice", "InvoiceLineItem", "Job", "JobAssignment", "JobChecklistItem",
  "JobEquipment", "JobLineItem", "Lead", "MaintenancePlan", "MaintenancePlanEquipment",
  "Notification", "Payment", "PriceBookItem", "Property", "Quote", "QuoteLineItem", "QuoteOption",
  "Reminder", "Supplier", "TechnicianLicence", "TimeEntry", "Session" CASCADE;
DELETE FROM "User" WHERE email <> 'admin@coolops.local';
UPDATE "Counter" SET value = 0;
COMMIT;

This removes all leads, clients, quotes, jobs, invoices, payments, the demo price book and the three demo staff logins, and restarts numbering at 0001. Then follow the first-day checklist, including changing the admin email and password.

9. First-day checklist

Log in as admin@coolops.local and work down this list.

  1. Secure the admin login. Go to Team, open Alex Morgan (the admin), change the name and email to your own and save. Then go to My account (round account button, top right) and change the password.
  2. Business details. Settings → Business: legal business name, ABN, address, phone, email, and upload your logo (PNG or JPG, under 2 MB).
  3. GST, terms and bank details. Settings → Invoicing: tick Registered for GST if you are, choose default payment terms, enter BSB and account details (they print on every invoice), quote validity days, invoice footer and quote terms and conditions.
  4. Numbering. Settings → Numbering: set prefixes (for example INV-) and, if you are moving from another system, set the next invoice, quote and job number so you carry on from where you were.
  5. Email wording. Settings → Email templates: adjust the subject and message for quotes, invoices, overdue reminders and service reminders.
  6. Job checklists. Settings → Checklists: edit the steps technicians tick off for each job type, one item per line.
  7. Add your staff. Team → Add user for each person: name, login email, mobile, role, calendar colour, hourly cost (for profit reports) and a starting password. Add each technician's licences (ARC, gas, electrical…) with expiry dates.
  8. Price book. Price book → New item for your common services, parts and units, with cost and sell prices (ex GST).
  9. Website form. Connect your website's enquiry form (section 29).
  10. Test the whole flow once with yourself as the client: lead → quote → accept → job → complete → invoice → payment.

  • The ⋯ button (More actions) on a record holds less common actions such as delete, duplicate or void.

12. Leads

A lead is an enquiry that is not yet a customer job. Website enquiries arrive here automatically; you add phone calls yourself.

Leads move through: New → Contacted → Site visit booked → Quoted → Won, or Lost.

How do I add a lead from a phone call?

  1. Go to Leads and click New lead.
  2. Fill in name, phone and/or email, suburb and postcode, Service, Source (Phone call, Google Ads, Referral…), urgency, estimated value and what they need.
  3. Optionally assign it to someone and set a Follow up on date. Save.

How do I move a lead along?

Use the Pipeline view and drag the card to the next column, or open the lead and change Lead status. Switch to Table view for a sortable list.

How do I turn a lead into a customer?

  1. Open the lead and click Convert.
  2. Pick an existing client or create a new one (choose client type and service address).
  3. Under Then choose Create a quote, Create a job (marks lead won), or Just create the client.
  4. CoolOps creates the client and property and takes you to the new quote or job. The lead is linked so reports can show which source won the work.

How do I mark a lead as lost?

Open it, click Mark lost and choose the reason (Too expensive, Went with another company, No reply, Not ready / timing, Outside service area, Did it themselves, Other). The reasons appear in reports so you can learn from them.

13. Clients, properties and contacts

  • Client: who pays. Types: Residential, Commercial, Real estate / Property manager, Builder.
  • Property: where the work is done. One client can have many (useful for agents and landlords). Each property has access notes, parking, pets and keys/lockbox details for technicians.
  • Contacts: other people at a client, such as a tenant or site manager.

How do I add a client?

  1. Clients → New client.
  2. Enter name, type, company (if any), email, phone, ABN for businesses, how they found you and the address. The address becomes their first property.
  3. Use Do not service to warn the office when booking work for difficult clients.

What is on a client page?

Tabs with everything about them: overview (properties, contacts, totals such as lifetime value and outstanding balance), their leads, quotes, jobs, invoices, payments, maintenance plans and an activity timeline. Add call notes with Add note.

How do I add another property?

On the client page click Add property. Open a property to see its equipment and job history.

16. Quotes

Statuses: Draft → Sent → Viewed → Accepted, or Declined / Expired (after the valid-until date).

How do I write a quote?

  1. Quotes → New quote (or convert a lead).
  2. Pick the client and site, give it a title and check the Valid until date.
  3. Add lines: from the price book or as custom lines. Each line has quantity, price and GST on/off. Totals and GST are calculated for you.
  4. Need choices? Add up to five options (for example Good / Better / Best, or 2.5 kW / 3.5 kW / 5 kW). The client picks one.
  5. Add an introduction and check the terms, then Save quote (or Save draft).

How do I send it?

On the quote page click Send. The client gets an email with a private link where they can see the options, download the PDF, and accept or decline online (to accept, they choose an option and type their name). When they open it the status becomes Viewed; when they accept, you get a notification.

Other buttons: PDF (download), Edit, and under ⋯: Copy client link (to paste into a text message), Open client view, Record acceptance or Record decline (when they tell you by phone), Duplicate, Delete.

Accepted. Now what?

Click Create job. The chosen option's lines are copied into a new job ready to schedule.

17. Jobs

Job types: Installation, Service / Maintenance, Repair, Emergency, Inspection, Warranty, Quote visit. Priority: Low, Normal, High, Emergency.

Statuses: Unscheduled → Scheduled → En route → In progress → Completed → Invoiced, plus On hold (for example waiting for parts) and Cancelled.

How do I create a job?

  1. Jobs → New job, or click an empty time on the Schedule, or Create job on an accepted quote.
  2. Choose client and site, job type, priority, title and description.
  3. Set start and end time (or leave unscheduled to book later) and estimated minutes.
  4. Choose the technician(s). Save.

What is on a job page?

  • Details and status buttons: On my way, Start job, Put on hold / Resume, Complete, Cancel.
  • Technicians assigned.
  • Checklist: added from the template for the job type (Add checklist), plus your own items.
  • Equipment at the site worked on in this job.
  • Parts and labour: lines that go on the invoice (Add part / labour or from the price book).
  • Time on site: starting the job starts a timer automatically; completing stops it.
  • Photos and files (before / after), notes, customer signature.
  • Completion details: work performed, refrigerant recovered and added (kg) and gas compliance certificate number.
  • Invoices raised from this job.

Under ⋯: Edit, Unschedule (moves it back to the unscheduled list) and Delete job (not possible once it has an invoice).

19. Technicians: My jobs

Built for a phone. Technicians log in at your web address and land here. Tip: on the phone, use the browser's Add to Home Screen so it opens like an app.

A typical job, step by step

  1. Open today's job from the list (In progress and Upcoming).
  2. Tap Directions to open the address in Maps. Check access, parking, pets and key notes.
  3. Tap On my way when leaving.
  4. Tap Start job on arrival. The time-on-site timer starts.
  5. Tick the Checklist as you go.
  6. Add Photos (choose before / after) straight from the camera.
  7. Add Parts & labour used and any notes.
  8. Fill in Completion details: work performed, refrigerant recovered/added, gas certificate number if gas work.
  9. Hand the phone to the customer for the Customer signature.
  10. Tap Complete. The office sees it straight away and can invoice it.

Waiting for parts? Tap Put on hold, then Resume later.

20. Invoices

Statuses are worked out automatically from the money and dates: Draft → Sent → Partially paid / Overdue → Paid, or Void.

Every invoice is a valid Australian Tax Invoice: your business name and ABN, the words "Tax Invoice", invoice number and date, the client (and their ABN), each line, GST and total, and your bank details.

How do I invoice a finished job?

  1. Open the job and click Create invoice.
  2. Choose Invoice the job in full. The job's parts and labour lines are copied in. Any deposit or progress invoices already raised are deducted automatically.
  3. Check it, then click Send.

Deposits and progress claims (big installs)

On the job, Create invoice → Deposit invoice… or Progress claim… and enter a percentage of the job value (30% is suggested for deposits). The final full invoice subtracts them.

An invoice without a job

Invoices → New invoice, pick the client, add lines, set issue date, due date and payment terms.

Buttons on an invoice

  • Send / Resend: emails the client a link to view and download the PDF.
  • PDF: download it yourself (to print or attach elsewhere).
  • Record payment: see Payments.
  • Edit: change lines or dates.
  • Under ⋯: Copy client link, Open client view, Mark as sent (if you gave it to them another way), Issue credit note, Void invoice, Delete draft.

Credit note or void?

  • Credit note: you need to reduce what the client owes (a discount after the fact, a returned part). Enter the amount inc GST and a reason. It gets its own number (CN-0001) and lowers the balance.
  • Void: the invoice should never have existed (wrong client, duplicate). It stays on record, marked Void, and is not counted.
Numbers never repeat

Invoice, quote, job and credit note numbers are given out one at a time and are never reused, as the ATO expects.

21. Payments

How do I record a payment?

  1. Open the invoice and click Record payment (or use the button on the Dashboard or Payments page).
  2. Enter the amount (inc GST), date received, method (Card (EFTPOS), Bank transfer, Cash, Cheque, Other) and a reference such as the bank transaction ID.
  3. Save. The balance and status update immediately: part payments show Partially paid, full payment shows Paid.
  • Refund: record a payment and tick This is a refund to the client.
  • Mistake: remove the payment from the invoice's payments list. The balance is recalculated.
  • The Payments page lists all money received with totals, filters and the most used method.

22. Maintenance plans

For clients on a regular service (for example an annual split system service). This is your repeat revenue.

  1. Maintenance → New plan.
  2. Choose client and site, give the plan a name, tick the equipment it covers, choose frequency (Monthly, Quarterly, Six-monthly, Yearly), price per visit (ex GST) and start date.
  3. Create plan. The Next service due date is worked out for you.
  • 14 days before a service is due, the client gets a reminder email and the office gets a notification.
  • Click Create job on a plan to make the service job. When that job is completed, the next due date moves forward by one period.
  • Untick Active to pause a plan; inactive plans do not send reminders.

23. Automatic reminders

Once a day (the scheduled task from section 5, step 7) CoolOps:

  1. marks unpaid invoices past their due date as Overdue and emails the client at 1, 7 and 14 days overdue (each only once);
  2. emails clients whose maintenance service is due within 14 days, and tells the office;
  3. warns about technician licences and equipment warranties expiring within 30 days;
  4. marks quotes past their valid-until date as Expired.

Nothing is ever sent twice, even if the task runs more than once in a day.

25. Team

  • Team → Add user: name, login email, mobile, role, calendar colour, hourly cost (wage plus on-costs, used for job profitability) and a password (at least 10 characters with a letter and a number).
  • Someone leaves: open them and untick Active. They can no longer log in and disappear from the schedule, but their history stays.

29. Website enquiry form

Your website's contact form can send enquiries straight into Leads. The office gets a notification and an email. If the same person enquires again within 24 hours (same email or phone), it is added to the existing lead instead of making a duplicate.

The form must send a POST request to https://YOUR-APP-ADDRESS/api/leads/webhook with the header x-api-key set to your LEAD_WEBHOOK_SECRET and a JSON body like this:

{
  "name": "Jane Citizen",
  "email": "jane@example.com",
  "phone": "0412 345 678",
  "suburb": "Brunswick",
  "postcode": "3056",
  "service": "Split system service",
  "brand": "Daikin",
  "message": "Two units, one is making a rattling noise.",
  "utm_source": "google",
  "utm_medium": "cpc",
  "utm_campaign": "aircon-service",
  "gclid": "abc123",
  "site": "coolingservicemelbourne.com.au"
}
  • name plus email or phone are required; everything else is optional.
  • utm_* and gclid come from your ad links. A gclid marks the lead as Google Ads so the Lead sources report shows your ad return.
  • Add a hidden, empty field called website to your form. Bots fill it in and are ignored.
  • At most 10 enquiries per minute from one address are accepted, to stop spam floods.

More than one website

All your websites use the same address and the same key. You do not need anything new in CoolOps for each site.

  1. On each website, point the enquiry form at https://YOUR-APP-ADDRESS/api/leads/webhook with the header x-api-key, exactly as above.
  2. Add one more field to each site's form called site, set to that website's name, for example melbourneaircon.com.au. In most form plugins this is a hidden field with a fixed value.
  3. Leads then show the website under their source, on the Leads board, in the table and on the lead page, so you can see which site brings in work.

If a form leaves out site but sends straight from the visitor's browser, CoolOps reads the website's address from the request automatically. Sending site is still the most reliable way.

If the forms send straight from the browser, list every website in LEAD_WEBHOOK_ALLOWED_ORIGINS, separated by commas, for example https://coolingservicemelbourne.com.au,https://melbourneaircon.com.au.

Who should connect it?

Give your web developer this section. The safest way is for your website's server to send the request (for example a WordPress form plugin with a "webhook" option, such as WPForms, Gravity Forms or Contact Form 7 with a webhook add-on), so the secret key is never visible in the browser.

Test it

curl -X POST https://YOUR-APP-ADDRESS/api/leads/webhook \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_LEAD_WEBHOOK_SECRET" \
  -d '{"name":"Test Lead","phone":"0400 000 000","suburb":"Richmond","site":"melbourneaircon.com.au"}'

A new lead called "Test Lead" should appear on the Leads board, showing Website form · melbourneaircon.com.au.

30. Inventory and van stock

What it does. CoolOps keeps count of the parts you stock (capacitors, filters, R32 and R410A in kg, drain pumps, isolators, brackets, pipe and so on) in the warehouse and in each technician's van. When a technician adds a part to a job, it comes out of their van by itself. When something runs low, the office gets a notification and the dashboard shows it. Every change is kept in a history, so you can always see why a number is what it is.

Setup (no API keys needed, it's built in).

  1. Go to Suppliers (left menu, under Admin) and click New supplier for each wholesaler you buy from: name, phone, email, your account number.
  2. Make sure each part you want to track is in the Price book as a Part or Equipment item, with its cost price. Labour and call-out fees can't be stocked.
  3. Go to Inventory and click Track item. Pick the part, set the Reorder level (for example 6 capacitors or 10 kg of R410A) and the usual supplier. Repeat for each part you keep.
  4. Load what you have now: on Inventory click Adjust / stocktake, choose the part and location, leave Change on Set to counted quantity, type the count and pick the reason Stocktake count. Do this for the warehouse and each van. (Or use Receive stock if the stock is arriving from a supplier.)

Each technician gets their own van automatically (for example "Jack Wilson's van"). Add a new technician under Team and their van appears.

Day to day: how do I…

  • …record a delivery? Inventory → Receive stock. Choose the supplier, Receive into (usually Warehouse), type the invoice or docket number, then add each item and quantity (Add item for more lines). The owner also sees Unit cost and can tick Update the price book cost price to what we paid to keep job margins accurate. Click Receive stock.
  • …load a van? Inventory → Transfer. From Warehouse to the technician's van, add the items and quantities, click Move stock. The form shows how many are on hand. Moving stock back to the warehouse works the same way.
  • …do a stocktake or fix a count? Inventory → Adjust / stocktake. Choose the item and location. Use Set to counted quantity to type what you counted, or Add / Remove for a known amount. Pick a reason (damaged, lost, returned to supplier…) and add a note if useful.
  • …see what's low? Inventory → Low stock. It lists parts whose total across the warehouse and vans is below the reorder level, with a Suggested order quantity. The dashboard's Low stock tile opens the same list.
  • …see one van? Inventory → Stock levels, then click the van name next to Location.
  • …find out where stock went? Inventory → Movements. Filter by Type or Location, or search for an item or job number. Job usage links to the job.
  • …export stock levels? Inventory → Export CSV (all locations, or the location you have selected). Opens in Excel.
  • …use parts on a job? Nothing extra: on the job, Add part / labour and pick the part. The toast says which van it came from and how many are left. Removing the line puts the part back. Lines that came from an accepted quote show a Take from stock link; click it once the parts are actually used.
  • …handle a negative number? It means more was used than the count showed (a red number and "Negative" flag). Recount with Adjust / stocktake, or record the delivery or transfer that was missed.
  • …stop tracking a part? Owner only: on the item's ⋯ menu click Stop tracking. Its history is kept.

Technicians open My jobs → My van stock on their phone to see what's in their van and recent movements. They can't change stock themselves; adding parts to their jobs does that.

Who sees what. Office staff can see and move stock and manage suppliers. Only the owner (admin) sees cost prices, stock value and can stop tracking items or delete suppliers.

31. SMS texts

CoolOps can text your clients automatically:

  • On my way: when a technician taps On my way on a job, the client gets a text with the technician's first name and your business name.
  • Appointment reminder: at 8am the day before a booked job.
  • Service due: when a maintenance plan is due within 14 days, together with the email reminder.
  • Overdue invoice (off unless you turn it on): at 1, 7 and 14 days overdue, with a link to view the invoice.

The office can also send a one-off text from any client or job page.

Every text is recorded. You can see it in the client's Activity tab, in the job's Activity card, and in Settings → SMS log.

Setting it up (once)

Until you connect an SMS provider, CoolOps only records texts (they show as "Logged only"). Nothing reaches clients. To start sending real texts:

Option A: MessageMedia (Australian company, recommended)

  1. Sign up at messagemedia.com (now part of Sinch) and add credit.
  2. In the MessageMedia Hub go to Settings → API settings and create a new API key. Choose Basic authentication, then copy the API key and API secret.
  3. Optional: buy a dedicated number so clients can reply, or register a sender name such as "CoolService" (clients can't reply to a sender name).

Option B: Twilio

  1. Sign up at twilio.com, upgrade to a paid account and buy an Australian mobile number (or register an alphanumeric sender ID).
  2. Copy the Account SID and Auth Token from the Twilio Console home page.

Then, in Coolify (your app → Environment Variables), add:

  • MessageMedia: SMS_PROVIDER=messagemedia, MESSAGEMEDIA_API_KEY=…, MESSAGEMEDIA_API_SECRET=…, and optionally SMS_FROM=+614… or your sender name.
  • Twilio: SMS_PROVIDER=twilio, TWILIO_ACCOUNT_SID=…, TWILIO_AUTH_TOKEN=…, SMS_FROM=+614… (your Twilio number, sender name, or Messaging Service SID starting with MG).

Redeploy the app. Integrations should now show the SMS card as MessageMedia or Twilio instead of Not set up. If something is missing, the card names the setting you still need to add.

Choosing which texts go out and what they say (admin)

  1. Go to Settings → SMS.
  2. Use the switch next to each automatic text to turn it on or off.
  3. Edit the wording in Message. Words in double curly brackets, like {{clientName}} or {{techName}}, are filled in automatically. The list under each box shows which ones you can use.
  4. The preview shows the text with example details, plus how many characters and SMS it uses. One SMS holds 160 characters; longer texts are billed as 2 or more. An emoji drops the limit to 70 characters per SMS, and the preview warns you.
  5. Click Save SMS settings.

The Running late and General message templates are only used for one-off texts.

How do I…

  • Text a client right now? Open the client (or one of their jobs), click SMS, pick a template from Template, edit the message, and click Send SMS. The counter under the message shows the length.
  • Stop texting a client who asked us not to? Open the client, click Edit, switch on No SMS, and click Save changes. They get no texts at all, and the SMS button explains why. A "No SMS" badge appears next to their name.
  • Find out why a client didn't get a text? Look at the job or client Activity, or Settings → SMS log. Each entry has a status: Sent, Logged only (provider not set up), Not sent (with the reason, e.g. "Landline number, can't receive texts" or "Client has opted out of SMS"), or Failed (the provider's error).
  • Which number is texted? The client's phone first, then their alt. phone, then their main contact's phone. The first mobile number found is used. Landlines and 1300/1800 numbers can't receive texts.
  • Clients marked "Do not service" don't get appointment or service-due reminders. On-my-way texts, overdue texts and one-off texts still work.

Costs: about 5–8c per SMS (one SMS = 160 characters). Reminders are factual service messages; keep marketing out of them, and mark anyone who asks not to be texted as No SMS.

32. Xero (live sync)

What it does

CoolOps can send your sales straight into Xero, so you don't have to type invoices in twice. It works one way, from CoolOps to Xero:

  • When you send an invoice (or use Mark as sent), it appears in Xero as an approved sales invoice with the same number. The job number goes in the Reference field, and every line is there with its quantity, price and GST.
  • The client is added to Xero as a contact. If Xero already has them (same email or same name), CoolOps uses that contact instead of making a second one.
  • Payments you record go into Xero against the invoice, into the bank account you choose. If you remove a payment in CoolOps, it's deleted in Xero too.
  • Credit notes go into Xero and are applied to the invoice.
  • Voiding an invoice voids it in Xero.

Nothing comes back from Xero into CoolOps. Keep making your changes in CoolOps.

Setting it up (one time, about 10 minutes)

You need to be an admin in CoolOps and be able to log in to your Xero organisation.

  1. Create a Xero app (this is free). Go to developer.xero.com, log in with your Xero login, and open My Apps → New app.
    • App name: CoolOps
    • Integration type: Web app
    • Company or application URL: your CoolOps address, e.g. https://app.coolingservicemelbourne.com.au
    • Redirect URI: your CoolOps address followed by /api/integrations/xero/callback, e.g. https://app.coolingservicemelbourne.com.au/api/integrations/xero/callback. (The Integrations page in CoolOps shows the exact address to copy.)
  2. In the new app, open Configuration. Copy the Client id, then click Generate a secret and copy that too.
  3. Give the keys to CoolOps. In Coolify, open the CoolOps app → Environment variables, add XERO_CLIENT_ID (the Client id) and XERO_CLIENT_SECRET (the secret), and click Redeploy.
  4. Connect. In CoolOps go to Integrations. The Xero (live sync) card now says Not connected. Click Connect to Xero, log in to Xero, and click Allow access. If you have more than one Xero organisation, choose Cooling Service Melbourne and click Use this organisation. The card then says Connected to ….
  5. Check the settings. Click Settings on the card (or go to Settings → Xero):
    • Sales account: usually 200 · Sales.
    • Tax rate for GST lines: GST on Income. Tax rate for GST-free lines: GST Free Income.
    • Bank account for payments: choose the account your customers pay into. Payments won't go to Xero until you pick one.
    • Send invoices to Xero as: Approved (recommended). If you choose Draft, you approve them in Xero yourself, and payments can't be added until you do.
    • Sync automatically: on (recommended). Turned off, nothing is sent until someone clicks Sync now.
    • Click Save Xero settings.

Invoices sent before you connected aren't copied across automatically. To send an older invoice, open it and click Push to Xero on its Xero card.

Day to day

How do I know an invoice made it to Xero? Open the invoice. The Xero card on the right says Synced, with an Open in Xero link. Each payment and credit note shows In Xero next to it.

Something says "Xero: failed". What do I do? The red text says why, for example Account code '999' is not a valid code or Can't reach Xero.

  • Connection problems fix themselves: CoolOps tries again automatically (after 1 minute, then 5 minutes, 30 minutes, 2 hours and 6 hours).
  • For anything else, fix the cause (usually in Settings → Xero), then click Retry on the invoice.
  • Office staff can see the Xero card and click Retry. Only admins can change the settings.

How do I see everything that was sent? Go to Settings → Xero sync log. Filter by Waiting, Failed, Done or Cancelled. Use Retry on one line, Retry all failed, or Sync now to send everything that's waiting.

How do I refund a client? First issue a credit note on the invoice for the amount you're refunding, then click Record payment and tick This is a refund to the client. Xero only accepts refunds against a credit note, so the refund fails without one.

I edited an invoice after sending it. The change is sent to Xero automatically. This stops working once Xero has a payment or credit on that invoice.

How do I disconnect Xero? Integrations → Xero (live sync) → Disconnect. CoolOps stops sending and gives up its access to Xero. Nothing already in Xero changes. If you reconnect the same organisation later, CoolOps carries on where it left off.

Does it work with MYOB? No. MYOB has no live sync. Use Integrations → Accounting export (CSV) → Download all invoices and import the file into MYOB.

Something to know: the daily reminder run also keeps the Xero connection alive. If nobody uses Xero sync for 60 days and the daily run isn't set up, Xero ends the connection, and you just click Connect to Xero again.

33. Google Calendar sync

What it does

Every job you're booked on shows up in your own Google Calendar — on your phone, your watch, wherever you already look. The office keeps working in CoolOps; the calendar follows along on its own.

Each event shows:

  • Title: J-0042 · Split system service · Jane Smith (a ✓ in front once the job is completed, "On hold ·" while it's on hold)
  • Where: the site address, so you can tap it for directions
  • Details: the client's phone number, the site address, access notes (gate codes, parking, pets, keys), what the job is about, who else is on it, and a link that opens the job in CoolOps

No prices, quotes or invoice amounts are ever sent to Google.

It's one way only: CoolOps → Google. If you move an event in Google Calendar, CoolOps does not change, and the next update from CoolOps puts the event back where the office booked it. To change a booking, ask the office (or change it in CoolOps).

When a job is rescheduled, changed, handed to someone else, taken off the schedule, cancelled or deleted, your calendar updates within seconds — including taking the job off the old technician's calendar and putting it on the new one's.

Each person connects their own Google account. Nobody can see anyone else's calendar.

Setup (one-off, by the admin / developer)

This is the only part that needs a computer and about ten minutes. It's free.

  1. Go to console.cloud.google.com and sign in with the business Google account.
  2. Top left, click the project picker → New project. Name it CoolOps → Create.
  3. With that project selected, open APIs & Services → Library, search for Google Calendar API and click Enable.
  4. Open APIs & Services → OAuth consent screen. Choose External, fill in the app name (CoolOps), your support email and developer email, and save. Under Data access / Scopes, click Add or remove scopes and tick:
    • openid
    • .../auth/userinfo.email
    • .../auth/calendar.events (Google Calendar API — "See, edit, share and permanently delete all the calendars you can access") Save. Under Audience, add each staff member's Google address as a Test user (or click Publish app so anyone in the business can connect — Google may ask for verification for published apps; test users work fine for a small team, up to 100 people).
  5. Open APIs & Services → Credentials → Create credentials → OAuth client ID. Application type Web application, name CoolOps. Under Authorised redirect URIs, click Add URI and paste exactly: https://your-coolops-address/api/integrations/google/callback (the exact address is written on the CoolOps Integrations page — copy it from there). Click Create.
  6. Google shows a Client ID and a Client secret. In Coolify, open the CoolOps app → Environment variables and add:
    • GOOGLE_CLIENT_ID = the client ID
    • GOOGLE_CLIENT_SECRET = the client secret Then Redeploy.
  7. In CoolOps, go to Integrations. The Google Calendar card should now say Set up instead of Not set up. Tell the team they can connect.

Day to day

Connect my calendar (everyone does this once)

  1. Click your name / avatar, top right → My account.
  2. Find the Google Calendar card → click Connect Google Calendar.
  3. Google asks you to sign in and to allow CoolOps to manage events. Tick the calendar permission and click Continue / Allow.
  4. You land back on My account with a green line: "Google Calendar is connected." Your next 60 days of jobs are added right away.

If the button isn't there and the card says Not set up, the admin hasn't done the setup above yet.

Check it's working

My account → the Google Calendar card tells you which Google account is connected, how many upcoming jobs are in your calendar and when it last updated.

My calendar looks wrong / I deleted an event by mistake

My account → Resync my calendar. This re-sends the next 60 days and puts back anything that was changed or deleted in Google.

Stop using it

My account → Disconnect. Your upcoming CoolOps jobs are removed from your Google Calendar (past ones stay as a record), CoolOps stops adding new ones and the permission you gave is withdrawn at Google. You can connect again any time.

"Reconnect needed"

Google sometimes drops the permission (password change, the permission removed in your Google account, or a long gap). The card says Reconnect needed — click Reconnect Google Calendar and allow access again. Nothing is lost.

For the office / admin

  • Integrations → Google Calendar lists everyone who has connected, which Google account, how many upcoming events they have, when their calendar last updated and any error. If something failed, a Retry failed button sends it again.
  • Team shows a Calendar connected badge next to each person who has connected.
  • Jobs are only on a calendar if the person is assigned to the job and the job has a date and time. Unscheduled, cancelled and deleted jobs are never on anyone's calendar.
  • The nightly reminders job also checks everyone's next 60 days, so even if something went wrong during the day it fixes itself overnight.

34. Route optimisation

What it does. CoolOps works out the order a technician should visit their jobs in so they spend less time driving, suggests new start times to match, and can change the bookings for you in one click (and undo it). Technicians get an "Open in Google Maps" button with all their stops in order.

Setting it up (once)

  1. Business address. Settings → Business: make sure the address is your depot / workshop. Every route starts and ends there.
  2. Start time. Settings → Routes → Day starts at (default 7:00 am) → Save.
  3. Technicians who take the van home (optional). Team → click the person → Route start → pencil icon → switch on Start from home, type their home address (e.g. 12 Smith St, Box Hill VIC 3128) → Save.
  4. Real drive times (optional, recommended). Without this CoolOps estimates driving from straight-line distances and only knows addresses to the suburb. To use Google Maps:
    • Go to console.cloud.google.com, sign in, create a project (e.g. "CoolOps").
    • Billing: add a card (Google requires it; normal use for a small business stays within Google's monthly free usage).
    • APIs & Services → Library: enable Geocoding API, Routes API and Maps Static API.
    • APIs & Services → Credentials → Create credentials → API key. Click the key, under API restrictions choose those three APIs, Save.
    • Give the key to whoever runs the server to add as GOOGLE_MAPS_API_KEY (in Coolify: the app's Environment Variables) and redeploy.
    • Then Integrations → Route optimisation → Geocode missing addresses. The card should now say Using Google Maps.

Day to day

  • Plan a technician's day: Schedule → (switch to Day and go to the day you want) → Plan route → pick the technician (and day) → Plan route.
  • Read the plan: the top shows Driving now, Driving with the plan and the Saving. The map shows the stops numbered in the new order (the dashed line is the current order). The table lists each job with its current time and the proposed time (changed times are highlighted).
  • Accept it: Apply new times → confirm. The Schedule board, the job timelines and the technician's Google Calendar update, and the technician gets a notification.
  • Changed your mind: on the same page click Undo next to "Route plan applied…". Jobs go back to their old times (any job moved by hand since is left as it is).
  • Stop a job being moved: open the job → Edit → switch on Time fixed (e.g. "customer only home 1–2 pm"). Emergencies, jobs already started and jobs shared by two technicians are never moved either.
  • Send the technician their route: they don't need anything: on My jobs they tap Open today's route in Google Maps (or the button for an upcoming day). You can also copy the Open in Google Maps link from the plan page.
  • A job says "no map location": check the site address on the client's page (street, suburb, postcode), save it, then Integrations → Geocode missing addresses.

37. Backups and restoring

Database (most important)

  1. Open the PostgreSQL database in Coolify and go to Backups.
  2. Add a scheduled backup, for example daily at 2 am (0 2 * * *), and keep at least 14.
  3. Strongly recommended: add an S3 storage destination in Coolify (Cloudflare R2, Backblaze B2, AWS) so backups are stored off the server. If the server dies, backups on it die too.

From the database's Backups list choose a backup and restore it (or download it and import with pg_restore / psql). Restoring replaces the current data with the backup's, so only do it when you mean to.

Uploaded files

Photos, signatures and the logo live in the /app/uploads volume. Back up the server (most VPS providers offer snapshots) or use S3 storage for uploads (STORAGE_DRIVER=s3), which keeps files off the server.

39. Questions and answers

Do I need Docker?

No. Coolify builds and runs the container for you. There are no Docker files in the code on purpose.

Can clients log in?

No. Clients never log in and there is no client portal. They only get a private link in each quote or invoice email to view and download that one document, and to accept or decline a quote.

Can clients pay by card online?

No. CoolOps has no online payments on purpose. Take payment in person or by bank transfer, then record it on the invoice with the method used: Card (EFTPOS), Bank transfer, Cash, Cheque or Other.

Can I continue my old invoice numbers?

Yes: Settings → Numbering → set the next invoice number.

I'm not registered for GST.

Untick Registered for GST in Settings → Invoicing. GST is no longer added and PDFs are titled "Invoice" instead of "Tax Invoice".

Can I delete an invoice?

Only drafts. Sent invoices are voided instead, so your numbering and records stay complete for tax.

How many users can I have?

As many as you like. There is no per-user cost.

Is my data safe?

Passwords are stored encrypted (hashed), every page checks the person's role, the site runs over HTTPS, and every change is recorded in the audit log. Keep daily off-server backups (section 37).

41. What's included and what's left out

Everything in the original plan is now built. The add-ons in sections 30 to 34 (inventory, SMS, Xero, Google Calendar, route optimisation) switch on when you add their keys; until then they stay quietly off.

  • Left out on purpose: online card payments (you record every payment yourself) and a client portal or client logins (clients only get a private link to each quote or invoice).
  • MYOB: there is no live MYOB sync. Use Integrations → Accounting export (CSV) and import the file into MYOB.
